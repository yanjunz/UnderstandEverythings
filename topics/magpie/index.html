Magpie 的运行原理

为什么 Claude Code 可以使用 DeepSeek？跟着一次请求，看看本地网关怎样选择模型、转换协议并返回结果。

先记住这一句：Magpie 是运行在你电脑上的模型网关：接住 Agent 的请求，找到合适的模型，必要时翻译双方的 API 格式，再把回复送回来。

两种讲解视角

初学者跟着一次请求理解网关的作用 架构师追踪接口、数据流和故障边界

初学者 · 从问题到回答

各方在请求中做什么

把这件事想成去一家有翻译服务的餐厅。你向服务员点菜，翻译协调口味和语言，真正做菜的还是厨师。

>_

Agent · 干活的助手

例如 Claude Code、Codex。它组织对话、读取项目，并在获得授权后执行工具。

就像服务员：接任务，安排事情。
⇄

Magpie · 中间的桥

管理接入配置，决定请求发给谁，并协调 API 格式、账号和回复。

就像翻译兼调度员：把双方接起来。
✦

模型 · 思考的引擎

例如 DeepSeek、Kimi。根据收到的上下文，生成文字或提出工具调用。

就像厨师：真正产出这道菜。

所以你可以保留熟悉的 Agent 操作方式，把背后的模型换掉。能否完整工作，仍取决于模型能力和协议兼容性。

第一次见这些术语？打开小词典 ＋
API / 协议
程序之间约定的沟通方式：请求发到哪里、字段叫什么、回复长什么样。
Provider / 服务商
提供模型服务的入口，包含地址、认证方式和模型列表；它也可以是本地模型服务。
Base URL
API 的基础地址，像收件地址。改向 Magpie 后，Agent 就先来找它。
流式输出
回复生成一点就传一点，因此你不必等全部写完才看到内容。
Token
在「消耗多少 token」里，它是模型处理文字的计量单位；在「认证 token」里，它指访问凭据。二者不是同一回事。

↳ 它怎么接到请求的？

Magpie 按不同 Agent 的配置格式，修改模型、基础地址等必要字段，让请求先发到本地网关。各 Agent 的具体接入方式不同，通常需要新会话或重启相关应用。

⌂ 这个地址是什么意思？

127.0.0.1 表示「这台电脑自己」，3425 是默认端口。外部 API 服务的凭据由 Magpie 管理；本地入口与上游认证是两层概念。

架构师 · 本地网关的接口与状态

沿着一次调用划分职责

以 Claude Code 经 Magpie 调用 DeepSeek 为例。Agent 按 Anthropic Messages 的接口发送「解释一下这个函数」，目标模型通过 Chat Completions 提供服务。这个案例采用普通模型 API 路径。路由实现

接入配置
internal/agent 按 Agent 的配置格式设置入口地址、认证和模型，并记录原设置以供断开时恢复。这个阶段建立本地入口指向。Agent wiring
请求路由
网关根据请求的模型或路由组，从已配置的服务商、账号和模型中选出候选。会话亲和性可以让连续请求留在已有账号上。Gateway routing
协议适配
跨协议时，入口解析为 Request 和 Part，再按上游协议构造请求。回程将流式事件重新编码回 Agent 的协议。中间表示源码

设计取舍。共用中间表示可以让各协议共用路由与转发逻辑。集成时仍要验证工具调用标识、结束信号和目标模型的能力。故障切换也取决于客户端是否已经收到回复，开始输出后需要保留已发送内容的语义。故障行为 · 协议表示

普通 API、订阅桥接与隐私边界

            

            

              

                A
                
执行工具，通常还是 Agent 的工作

                

                  模型可以返回「调用 read_file」的结构化请求。Magpie 把它转成
                  Agent 理解的格式，由 Agent
                  检查权限并执行，再把结果带到下一轮。
                

                

                  模型提出调用→Agent 执行→结果进入下一轮
                

                

                  这是普通模型 API 路径。Magpie 另有
                  MCP、内置工具和订阅桥接等功能，不能把所有路径都等同于这一条。
                

              

              

                B
                
订阅接入，不全是直接转发 HTTP

                

                  API key 服务商、本地模型和订阅账号的接入方式不同。例如 Claude
                  订阅路径会驱动本地真正的 claude 程序，并通过 MCP
                  桥接工具。
                

                

                  MCP 是连接工具与 AI
                  应用的一种协议。理解主干后，再研究具体订阅的认证与进程管理，会更容易。
                

              

            

            

              ◇
              

                

                  「本地网关」意味着请求先经过本机，不等于全部在本地推理。
                

                

                  选择云端模型时，请求仍会离开电脑。Magpie
                  有可选的隐私脱敏功能，默认关闭；开启后会尝试把识别到的敏感值换成占位符，回复时再还原。它不是「任何信息都不会外传」的保证。
