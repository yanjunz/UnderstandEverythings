pstack Skill 原理

关掉通知，点了保存，刷新页面却又变成开启。一个编码 Agent 收到这条报告后，该先改代码，还是先复现？pstack 把这类决定写成一套可按需加载的工作流程。它原本是 Lauren Tan 的 Cursor 技能栈，本文分析 Michael Denyer 维护的多宿主移植版。[1]

两种讲解视角

初学者一次修复为什么需要一张清单 架构师路由、流程组合与执行边界

把「修一下」变成一项能验收的工作

pstack 是一套给编码 Agent 读的 Skill，也就是做某类工作的说明。poteto-mode 是入口。任务简单时直接处理，像通知设置这种原因未知的故障会进入 Bug fix Playbook。Playbook 就是针对一种任务写好的步骤清单。[2][3]

  1. 先看到问题。 关掉通知，保存，刷新。刷新前显示「关」、刷新后显示「开」，这才是要修的现象。
  2. 沿着证据找原因。 教学示例里，委派调查查明保存动作只改了页面里的临时状态。于是只改保存这条路径。
  3. 用原来的方式再试一次。 再做一遍「关掉、保存、刷新」。刷新后仍然是「关」，才能确认用户遇到的现象消失。[4]

为什么要登记步骤？

一项工作可能做到一半才发现某步不适用。pstack 要求把该步留在清单并写明跳过原因。回看时，你能知道哪些检查确实做过、哪些只有理由。[3]

工作流由 Markdown 描述，由宿主工具执行

以 Claude Code 插件为例。注册、文本注入和工具调用发生在不同阶段。通知设置故障会依次经过路由、流程选择、调查与实现、验收。[2][3]

会话钩子提供入口
hooks/hooks.json 在启动、恢复、清空或压缩会话时调用 session-start.sh。启用时，脚本返回 session-start-context.md 的路由文本。模型读到「原因未知的故障」等触发条件后加载 poteto-mode。用户明确要求 tdd 等专门 Skill 时，可以直接进入相应流程。[2]
Playbook 按需组合，清单记录进度
poteto-mode/SKILL.md 先按任务选 playbooks/bug-fix.md 或 feature.md，把步骤放入宿主待办，缺少待办工具时可用未提交的 Markdown 清单。遇到需要验证的判断再读对应的 principle-*，例如 principle-prove-it-works。项目 Playbook 可以用 extends 扩展内置步骤，check-playbooks.mjs 会检查版本变动后引用的步骤是否仍存在。[3][6]
主 Agent 持有验收责任
主 Agent 亲自复现、界定调查或实现任务，并将 worker.md 的路径传给子 Agent。Claude Code 可使用 pstack:poteto-agent；子 Agent 回传证据或改动，主 Agent 审 diff 并在原界面复测。如果改动涉及接口、所有权或数据语义，Bug fix Playbook 会先走 architect。某些改动还要求独立正确性审查，缺席时对应的合并就绪门槛保持关闭。[3][4][5]
验收看同一路径上的行为
如果有便宜的回归测试路径，tdd 先确认修复前因预期的值不匹配而失败，再确认修复后通过。通知设置的界面复测依然要执行「关闭 → 保存 → 刷新」。只测保存函数时，浏览器的数据依然有可能恢复成旧值，按原故障路径判断应记作未确认。[4][7]

同一套 Skill 怎样跑在不同宿主？

各移植版共享 plugins/pstack/skills/。Markdown 以 Claude Code 的工具词汇为主，移植版为各宿主提供映射。比如在 Codex，Agent 的委派动作映射为 spawn_agent，插件钩子需受信任才运行。在 DeepSeek Harness，skills-only 装法只提供技能文件，用户显式请求 poteto-mode，委派使用宿主暴露的 subagent 等工具。[8][9][10]

移植仓库同步 Cursor 上游时，先应用 Cursor 到 Claude Code 的机械转换，再保留 tools/forks.json 明示的宿主适配或工作流差异。这样，共用的 Skill 只维护一份，宿主之间的工具差异由各自的映射处理。[8]

设计取舍

按需加载便于复用流程，也让一项任务只读需要的规则。代价是路由和大部分步骤依赖模型遵守指令，跨宿主还要核对工具和权限。脚本能检查步骤锚点等可机械判定的条件。真实行为是否修好，仍需看实际执行产生的证据。[3][6]

读者问题

pstack Skill 的原理是什么？
把做事方法写成可组合的技能文件，由 poteto-mode 选择 Playbook。主 Agent 把步骤登记成待办，按需调用子技能、子 Agent 和宿主工具，最后用实际产物验证结果。[3][4]
装了 Skill，流程就一定会执行吗？
自动路由取决于宿主集成和钩子状态。启用的会话钩子提供提示，选择和执行仍由模型与宿主完成。skills-only 安装可显式调用，实际能否委派或操作界面取决于宿主开放的能力。[8][10]
